# Прогноз отклика на предложение банковского вклада

Задача — ранжировать клиентов до звонка по вероятности открыть срочный вклад. Для оценки предполагаем, что банк может обзвонить 10% списка. **Precision@10%** показывает долю открытий среди этих 10%, выбранных моделью. Average Precision (AP) дополнительно оценивает качество ранжирования по всей выборке.

## Итоговые результаты

**На тесте по основной метрике выиграло дерево решений.** Дерево поставило в первые 678 позиций 360 записей с открытым вкладом, CatBoost — 326. CatBoost лидировал на валидации и немного опередил дерево по AP на тесте.

| Подход | Precision@10%, валидация | AP, валидация | Precision@10%, тест | AP, тест |
| --- | ---: | ---: | ---: | ---: |
| Случайный отбор, ожидаемое значение | 11,52% | — | 39,34% | — |
| Дерево решений с one-hot кодированием | 20,80% | 0,1595 | **53,10%** | 0,4633 |
| CatBoost, эксперимент № 3 | **29,79%** | **0,2389** | 48,08% | **0,4668** |

## Данные и проверка моделей

В `bank-full.csv` 45 211 записей о телефонных кампаниях португальского банка. В 5 289 случаях (11,70%) клиент открыл вклад (`y=yes`). Строки упорядочены по дате, поэтому их разделили без перемешивания. Первые 70% пошли на обучение, следующие 15% — на валидацию, последние 15% — на тест. [Датасет UCI Bank Marketing](https://archive.ics.uci.edu/dataset/222/bank%2Bmarketing)

Доля открытий менялась от **5,81%** на обучающем отрезке до **11,52%** на валидационном и **39,34%** на тестовом. Для случайного отбора ожидаемая Precision@10% равна доле открытий в соответствующем периоде. В валидации и тесте по 6 782 записи, из каждой выборки берём первые 678 позиций рейтинга.

Из признаков исключили `duration`, поскольку длительность разговора известна после звонка. Эффект модели в реальной кампании можно измерить A/B-тестом со случайным отбором при одинаковом бюджете звонков. [Постановка задачи](notebooks/01_data_and_business.ipynb)

## Почему выбрали эксперимент № 3

У исходного CatBoost Precision@10% на валидации составила 27,43%. После добавления флага `pdays_prev_camp` и замены `pdays=-1` на пропуск она выросла до 29,35%. Значение `-1` означает, что клиента ранее не обзванивали в рамках прошлой кампании. Подбор параметров поднял Precision@10% до **29,79%**. В итоговой конфигурации CatBoost 1 000 итераций, `depth=8`, `learning_rate=0.01`, `l2_leaf_reg=3`, `loss_function="Logloss"` и `random_seed=0`.

Логарифмирование, признаки по профессии, отношение баланса к возрасту и кластеризация уступили эксперименту № 3 по Precision@10%. Ближе всего из этих вариантов оказался признак отношения баланса к возрасту с Precision@10% **28,02%**. [Разбор экспериментов № 1–9](notebooks/04_experiments.ipynb)

## Ограничения валидации

Слабое место валидации — одно хронологическое окно. В нём были записи только за апрель и май, поэтому и подбор параметров, и сравнение моделей зависели от состава этих двух месяцев. На тесте весь топ‑678 дерева пришёлся на февраль, март и октябрь. При переобучении дерева без `month` и `day` его Precision@10% на том же тесте снизилась с **53,10% до 44,54%**.

### Как улучшить проверку

1. **Проверять доступность признаков на момент отбора.** В CSV `contact`, `day` и `month` относятся к последнему контакту текущей кампании, а `campaign` включает этот контакт в число звонков. Для отбора до первого звонка использовать только значения, известные при формировании списка. Признаки, которые появятся позже, исключить из обеих моделей. [Описание полей UCI](https://archive.ics.uci.edu/dataset/222/bank%2Bmarketing)
2. **Сравнивать модели на нескольких последовательных окнах.** Обучать обе модели на ранних строках, проверять на следующем блоке, затем расширять обучающий период. Для выбора модели и параметров сравнивать Precision@10% по окнам, её среднее и разброс. Отдельный поздний период оставить для финального теста после выбора модели и признаков.
3. **Считать метрику при реальном бюджете.** Если список формируется каждую неделю и бюджет составляет 10% от него, выбирать топ‑10% отдельно для каждой недели. Итоговая метрика — доля открытий вклада среди всех выбранных клиентов.

## Как воспроизвести

1. Скачайте архив с UCI и извлеките из вложенного `bank.zip` файл `bank-full.csv` в `data/`. Ноутбуки читают `data/bank-full.csv` с разделителем `;`. [Страница датасета](https://archive.ics.uci.edu/dataset/222/bank%2Bmarketing)
2. Из корня репозитория выполните команды ниже. Четыре зависимости ноутбуков устанавливаются отдельно, поскольку их нет в `pyproject.toml`.

   ```bash
   uv sync --locked --python 3.9
   uv pip install --python .venv/bin/python catboost==1.2.10 scikit-learn==1.6.1 seaborn==0.13.2 importlib-metadata==8.7.1
   PYTHONPATH="$PWD" uv run --no-sync jupyter lab
   ```

3. Откройте ноутбуки из папки `notebooks/` и запускайте ячейки сверху вниз. Для воспроизведения таблицы достаточно ноутбуков `03` и `04`.

   - Постановка задачи и обзор данных. [01_data_and_business.ipynb](notebooks/01_data_and_business.ipynb) · [02_eda.ipynb](notebooks/02_eda.ipynb)
   - Базовые подходы. Последняя ячейка выводит Precision@10% и AP дерева на тесте. [03_baseline.ipynb](notebooks/03_baseline.ipynb)
   - Эксперименты с CatBoost и метрики итоговой конфигурации. [04_experiments.ipynb](notebooks/04_experiments.ipynb)
